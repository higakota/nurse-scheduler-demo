# 開発で見直した判断

## 自動作成の後の変更を中心に考える

最初の配置だけでなく、勤務希望や応援の予定が変わった後にどの表を使うかが課題になった。作成・編集・印刷の入口をまとめ、元の表の版を持って変更確認へ進むようにした。[古い表が開く問題の修正](case-studies.md#1-編集後に古い勤務表が開く)に、保存前の不変も含めて記録している。

## 応援スタッフを一律に扱わない

事前に来られる日が分かっている人と、相談後に来院が決まった人では再配置できる範囲が異なる。依頼済みの応援を守りながら自院を調整する条件へ整理した。[了承変更の事例](case-studies.md#3-了承出勤後の連勤を調整する)で、連勤・公休日数・取り消しを検証している。

## 試した表示を戻すことも改善に含める

応援をまとめる案は画面では読みにくく、個人別表示へ戻した。印刷では集約を残した。[表示の見直し](case-studies.md#5-見やすさの改善案を利用者の反応で見直す)に、試行と修正の両方の履歴を残した。

## 確認済みの成果と未測定のことを分ける

テストで確認した処理・条件は記録する。業務時間の削減率や導入効果は測定していない。生成AIを実装・調査・テスト作成に利用したことも明記し、変更の具体例と確認方法を説明できる形にしている。
