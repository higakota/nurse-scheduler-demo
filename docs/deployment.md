# ブラウザ体験版の公開

**[公開中のブラウザ体験版を開く](https://nurse-scheduler-demo.onrender.com/?month=2026-11)**

RenderのFreeプランで公開しています。READMEは動画を先頭に置き、その下に体験版とサンプルExcelの入口をまとめています。

## Renderで作成する

[Renderに配置する](https://render.com/deploy?repo=https://github.com/higakota/nurse-scheduler-demo)

1. Renderへログインし、上のリンクを開く。
2. 公開リポジトリの `render.yaml` を読み込む。
3. 作成するサービスが `nurse-scheduler-demo`、プランがFreeであることを確認して作成する。
4. ビルドが成功したら、Renderが発行するURLを開く。

通常の起動にPowerShellは不要です。設定の詳細は [Blueprint仕様](https://render.com/docs/blueprint-spec)、無料枠の休止・データ消去の条件は [Render公式の制限](https://render.com/docs/free) を参照してください。追加料金が発生する設定へ変更しないでください。

## 体験版の保存

- ブラウザごとにランダムなIDを発行し、署名付きのHttpOnly・Secure Cookieへ保存する。
- スタッフ、入力、作成表、バックアップ、復元用ファイルは利用者別のフォルダへ保存する。
- 同じブラウザのタブは同じデータを使い、別のブラウザ・シークレットウィンドウは別のデータを使う。
- 同一利用者の処理は順番に実行し、別利用者のデータへ保存先が切り替わらないようにする。
- 初回は架空データを作成する。「初期状態に戻す」は操作した人だけを新しい架空データへ切り替える。
- 24時間使われていないデータは、次のアクセス時に削除する。最大256組の保存先を設け、空きがない場合は案内を表示する。
- 無料サービスの休止・再起動・再配置で操作内容が消える。Cookieの削除後も新しい体験になる。実務のデータ保存には使わない。
- 実在する職員の氏名、実際の勤務表やExcelは入力・アップロードしない。

## 実行構成

`web_entry.py` が公開用の入口です。`demo_run.py` は従来どおりローカル用です。公開側の入口はローカルDBを読み込みません。

Gunicornは1ワーカー・4スレッドで起動します。利用者ごとの排他制御をプロセス内で行うため、ワーカー数・インスタンス数を増やす場合は設計の変更が必要です。秘密鍵はRenderが環境変数 `DEMO_SECRET_KEY` として生成します。ソースには保存しません。

## 公開URLでの確認

Render上で、入力画面の表示、仮作成、ヘルプ反映、保存、希望との比較を確認しました。独立した2つのブラウザでスタッフ編集とダウンロードしたバックアップが分離され、Secure・HttpOnly Cookieが使われることも確認しました。確認中のJavaScript例外とサーバー500番台エラーは0件でした。

## 検証

- `tests/test_web_demo.py`：利用者の分離、バックアップ、初期化、CSRF、保存先の検証、同時アクセス、期限切れの削除、容量上限、実際の画面経由の分離。
- `tools/check_web_deploy.py`：LinuxでGunicornを起動し、HTTP経由で2人分の表示・編集・バックアップの分離を確認する。
- GitHub Actionsの `web` ジョブが公開用の依存関係とGunicorn起動を確認する。

この体験版には実務用のログイン・権限管理はありません。実用版をインターネットへ公開するための構成ではありません。
